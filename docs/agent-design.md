# Jane Agent 设计

设计基线 v0.9 · 2026-11-12。P1 已扩展动态主题目录和难度，P2 自由聊天仍为设计；验收状态见开发节奏。产品流程见 [产品细则](product.md)，保存规则见 [数据契约](data-contracts.md)。

## 1. 职责与课程配置

Jane 是唯一可见助教。场景目录规划师独立于 Jane 教学配置；主题规划和评估也按用途使用不同指令与 outputType。程序直接选择工厂，不经 handoff，不让模型自主路由或读写文件，不建设多角色协作平台。

- 人工配置：固定场景及范围、安全要求、三档难度指导、3–8 主题和每主题 8–15 问的边界。
- 场景规划 Agent：首次开始场景生成主题名称、训练范围与排除边界，覆盖高频需求，核心目标不过度重叠。
- Jane 主题规划/教学 Agent：根据已保存主题和所选难度生成本次虚构情境和对话；提问、提示、判断、解释、衔接和结束鼓励。
- 程序：校验计划与输出；分配 ID，管理轮次、状态、保存、去重和模式切换。

入住人数、日期、早餐时间等不硬编码在课程配置中。每次主题开始由 Agent 生成一次，程序保存为会话事实；同一会话不能无声改变。用户主动修改需求时记录事实变更及对应原文。不收集真实证件、不声称办理现实酒店业务。

### 1.1 场景初始化

“开始场景”才生成目录，读取和刷新不触发。输入固定场景 id/title/scope；输出 topics 数组，每项 title/scope/boundaries，数量 3–8，ID 由程序分配。提示词要求高频、覆盖广、粒度相近、按旅程顺序、合并相似任务，生成前自行核对但不输出推理过程。实现见 agents/prompts/scene.ts。

Zod 检查结构、数量、长度；程序拒绝规范化后重复的标题/范围。语义重叠和覆盖质量仍需提示词及人工抽查，不能由 schema 完全保证。成功后把课程元信息、主题与回执一次提交到 SQLite；重复初始化直接复用，不重置进度。失败不保存半个目录，不回退写死主题。

目录在当前版本固定不变，切换难度不重建。旧酒店记录迁移时保留原四主题，其后续主题现已可练。

### 1.2 三档难度

默认 medium（中等，高中/大学日常英语）；easy（简单，小学/初中基础词与短句）；advanced（高级，面向雅思/托福学习者，更丰富词汇、条件/比较/原因表达），不是考试等级认证。

profile.difficulty 是新主题偏好，开始主题时写入 configSnapshot.lesson.difficulty。规划、后续提问、中文任务、提示和纠错都使用该快照；旧对话不因首页切档而改变。旧 A1–A2 解析为简单。高级仍接受语义正确的简短回答，不因表达“不够高级”记错，不堆砌生僻词。

## 2. 本次对话计划

目录生成后按顺序开始下一未完成主题；每主题正常只进行一次对话，未完成优先续学，明确重练才新建记录。开始主题时调用 Agent，生成：

- 适合本场景的虚构角色和服务事实，不把酒店入住字段强加到其他主题。
- 8–15 个不同训练问题，每项包含英文问题、对应的中文翻译、中文作答意图、内部参考答案、表达目标短标签。

`chineseTranslation` 只翻译对应的 `english`，不是指导用户回答的 `chineseTask`，不得补出用户答案。后续 continuation 改写英文时同步生成实际问句翻译；不沿用可能过期的计划翻译。角色回应使用独立的 `roleplayTranslation`，只翻译本次 `roleplayLine`，不借用教学反馈。新模型输出必须带角色回应翻译，服务端改写角色回应时同步更新译文。历史缺失保持缺失，不自动付费回填；结束语和用户输入不在翻译范围内。

角色回应与下一问保留独立气泡，均复用点击显示中文、再次点击英文或中文关闭、10 秒自动关闭的交互；手动关闭同时取消计时器。
- 合理顺序与结束点。

程序分配计划/问题 ID，检查数量、字段、长度及主题标识；schema 不能证明语义相关或事实正确，仍需提示词约束与人工抽查。失败不创建可练会话，不用假对话替代，不无限自动修复。恢复读取原计划；重练才生成新计划。普通页面视图不下发内部完整参考答案。

计划是参考路线，不是固定剧本。Agent 可调整措辞与剩余问题顺序，但只能选择已生成的未处理项；用户提前提供信息时，模型可提出“提前覆盖”的问题 ID 与原文证据，程序校验引用范围并记录，避免重复提问。不建设复杂目标调度器。

8–15 是初始计划范围；提前覆盖后实际问题可少于八个，不凑数。最多展示 15 个不同训练问题；求助、解释、澄清、重答不增加问题计数。初版不临时新增计划外训练题。到上限仍有未解决项时保留补练/暂停，不能假完成。

## 3. 上下文与动作

训练输入包含当前主题/计划、当前英文问题与中文意图、已确认事实、问题状态、本次 action/text，以及最近可见对话（建议最多 6 个完整回合并限制字符数）。重要事实变更和提前覆盖证据保存在 turns.payload.effects，当前事实和已解决题目通过 selectors 计算；模型上下文裁剪不删除数据库历史。

用户动作：answer / hint / explain。answer 非空；hint 可无文本；explain 可针对词句。自然语言求助同样识别，不计错、不推进。程序直接追加 question/completed，不为自动推进产生请求编号；continue 接口仅恢复旧的已保存待继续状态，不新增模型调用或 continue 事件。

用户输入建议最多 2,000 字符，超长明确提示，不静默截断。用户内容不得拼成可信系统规则。不发送整本错题、文件路径、密钥；不同时叠加本地完整历史和云端会话历史。

## 4. 最小结构化评估

以下字段已在 src/contracts 用 Zod 单一实现，不在各文档复制 schema：

| 字段 | 用途 |
| --- | --- |
| learnerIntent | answer / hint / explain / off_topic |
| verdict | correct / needs_correction / uncertain / not_applicable |
| canContinue | 是否已表达清楚，与有没有小语法错误分开 |
| correctedAnswer / explanation | 纠正表达与说明，可空 |
| errorTypes | grammar / meaning 数组，无明确错误时为空 |
| roleplayLine / tutorFeedback | 英文角色台词与教学说明分别呈现 |
| hint | 求助时提供关键词、句式或参考回答，否则不暴露完整答案 |
| continuation | 可继续时的下一问题 ID、问法与中文任务；无剩余项则为 closingMessage |
| 可选事实变更、提前覆盖证据 | 引用本计划问题和本次原文，不由模型生成会话 ID 或轮次 |

程序校验：
1. 仅 answer 动作且识别为符合当前任务的英文作答或数字回答可推进；数字是否有效由 Agent 结合当前问题判断，不再用“必须含英文字母”一刀切。求助、偏题、全中文、uncertain 均不推进。
2. needs_correction 必须带明确 errorTypes、非空纠正与解释；纯自然度建议不记错。
3. 轻微语法错误但意思清楚，可 needs_correction + canContinue=true：记错并允许继续；含义不符或影响理解则重试。
4. correct 必须 errorTypes=[]；Check in, please. / Two adults and a child. 等语境正确的短句可接受，不做逐字匹配。
5. 全中文只引导英文表达，不伪造语法错题。对于校验通过且不推进的 unclear/off_topic 反馈，或被拒绝的无英文字母作答，程序统一整理为 uncertain 和「我还没理解你的意思。试着用英语表达：当前中文任务」，清空语言错误及参考答案。有效英文的真实语法/含义错误仍保留纠正。此整理在业务校验后进行，不把坏模型输出伪装成教学反馈；网络与解析失败也不属于语言错误。
6. 下一项必须在计划中且未解决；全部项已作答或具有有效提前覆盖证据时才接受候选结束。冲突输出报错保留状态，不擅自修成通过。

错题由程序根据已提交评估派生，不从台词猜测；场景/主题/轮次/原文由程序关联，模型不用重复生成。

## 5. 状态与结束

2026-11-12 更新：回答通过后自动衔接下一问。正常请求中 active → awaiting_continue → active / topic_completed 在同一候选副本中执行，一次落盘；awaiting_continue 不是正常作答中的可见暂停步骤；它仍是候选推进和待继续恢复使用的状态。

- 创建：生成、校验并保存计划后展示首问及中文任务。
- 作答可继续：校验 feedback、effects 和下一步候选，追加教学事件并自动推进；反馈与实际下一问/结束语一次性保存。前端保留反馈，直接更新当前问题、中文任务和输入框，不再显示逐题“继续”。
- 需修改、澄清、求助：保留 active 与当前问题。
- 自动推进：回答与实际 question/completed、会话状态和成功回执同事务保存；一次操作 revision +1，事件分别按 sequence 排序，不保存 continue。最后一项提交 topic_completed，结束语来自 completed 事件。
- awaiting_continue 会话提供一次“恢复对话 / 查看完成结果”入口；GET 不偷偷写入，恢复后按新规则自动衔接。
- 最后一次评估同时生成结合真实表现的鼓励/幽默结束语，不额外调用“鸡汤生成”，不虚构全对。缺少有效结束语时该结果不完整，可显式重试。
- 调用、校验、保存失败不推进。P1 起保存成功再展示。“主题完成”不等于“整个场景完成”。

## 6. 自由聊天（P2，尚未实现）

主题结束语后主动选择“继续任务：下一主题”或“和 Jane 自由聊聊”。无可用下一主题时，第一个入口改为已实现的复习/返回场景。

自由聊天新建独立 mode=free_chat 会话，关联 sourceTrainingSessionId。Jane 恢复助教/朋友身份，只输出普通可见回复，不套训练评估字段。默认只带自由聊天历史和来源主题名，不自动复制训练历史；自由聊天也不注入后续训练评估。

不修改训练进度、不自动计错；可主动收藏。聊天中的“开始下一课”不直接改状态，需用户点击明确入口。返回训练读取独立记录，失败保留草稿，保存保证与训练一致。

## 7. 实施与验证

沿用现有 SDK/Runner，默认关闭 tracing；无 tools/handoff。计划生成预算需容纳 8–15 问，不沿用欢迎语 128-token 特例；P1 小量验证后确定预算，不自动批量评测。

[OpenAI 官方 Agent 定义](https://developers.openai.com/api/docs/guides/agents/define-agents) 支持 outputType 结构化结果；本项目用于目录、主题计划与评估，状态仍由程序管理。接入细节见 [接入指南](openai-setup.md)。

人工检查：计划长度与主题、事实一致、正确变体、轻微语法错误记错但可继续、含义错误重答、提前信息不重复问、提示不推进、结束语真实、自由聊天隔离、失败与恢复。P1 在网页完成训练、保存与恢复闭环；P2 再验证独立自由聊天。
